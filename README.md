# 群 Key 池机器人（qq-keypool-bot）

一个跑在 QQ 群里的**共享 API Key 池**：群友把自己愿意公开的中转站 key 投进池子，
其他人在群里用指令随时查；机器人每小时自动刷新每个 key 上各模型的可用率，判死的
key 直接删掉，还可以每天定时往群里播报一次池子情况。

> 本来只是自己群里用用的简单脚本，但是有群u问我代码，就在此开源，实现逻辑只是很简单小代码。
> 这个脚本的诞生之初也只是因为有群u免费提供key，却总是因为消息被冲走导致没人用罢了。

* **纯 Python 标准库**：零第三方依赖，`python3` 直接跑。
* **全程不使用任何大语言模型**：指令是固定字符串解析，回复是固定模板拼接，模型状态是
  固定分支判档——不会把 key 抄错，不会被群消息里的文字当成指令执行，也不会让模型去
  「判断」和「编造」任何东西。
* **不包含聊天客户端**：只按 OneBot v11 协议收发，用什么实现（NapCat、Lagrange、
  go-cqhttp…）由你自己挑，见 [部署说明](DEPLOY.md)。

## 能干什么

| 功能 | 说明 |
|---|---|
| 🗂 共享 key 池 | 群友 `/提供` 投 key，其他人 `/列表` 看、`/查询` 用（余额 + 地址 + 密钥） |
| 📊 模型可用率 | 每小时采集各站点公开的 `pricing` + `perf-metrics`，算出每个模型的**可用率**，低于 60% 标红叉 |
| 🗑 自动清死号 | 明确「余额耗尽」或站方明确回「令牌无效」的 key，直接从池子里删掉 |
| ☀️ 每日播报 | 定时把「今天谁投了 key + 池子里现在几个」发到群里 |
| 🏘 分群分池 | 默认**每个群一个独立的池**（序号各自从 1 开始），也可以配成所有群共用一个池 |

## 指令

群里直接发（不需要 @ 机器人，也可以 @）：

| 指令 | 作用 |
|---|---|
| `/列表 [页数]` | 看本池所有 key（每页 5 个） |
| `/更新` | 立刻刷新本池的模型状态 |
| `/查询 <序号>` | 当场测活这个 key，回余额 + 地址 + 密钥 |
| `/查询全部` | 检测本池全部 key 并删除失效的（静默，不回复） |
| `/提供 站名 你的昵称 地址 密钥` | 投一个 key 进本池 |
| `/删除 <序号>` | 直接删除（不可恢复） |
| `/检测列表更新 模型名…` | 重设本池的检测名单（整体覆盖，空格分隔） |
| `/帮助` | 用法说明 |

`/列表` 长这样（`#N` 是序号，`【✅】` 可用、`【❌】` 可用率低于 60）：

```
📋 群 Key 池
━━━━━━━━━━━━━━
#1 某中转
└ by 小明
　gpt-5.6-sol【✅】可用率99% ｜ claude-opus-5【✅】可用率97%
　grok-4.6【❌】可用率42% ｜ kimi-k3【✅】

#2 另一个中转
└ by 小红
　待检测

━━━━━━━━━━━━━━
🕐 更新于 09-13 18:23
📄 第 1/1 页
```

## 三个概念：池 / 序号 / 检测名单

**池（pool）** = 一个独立的 key 集合。默认 `pool_mode: "per_group"`：每个群一个池，
A 群投的 key 在 B 群看不见（`/查询`、`/删除` 也都只在本池里找，找不到就静默不回复）。
想让所有群共用一个池，改成 `"shared"`。

**序号（#N）** 是**池内**序号，每个池各自从 1 开始：

* 上限 **99**，一路往上加，到顶后回绕回 1，再找第一个空号；
* 99 个号全被占用时池子算满，`/提供` 会回复「池子满了」，**不会覆盖**已有 key；
* 删除**不会**立刻回收序号——被删掉的号要等计数器回绕到末尾之后才会被复用，
  所以群友手里缓存的「#3」过一阵子可能已经不是原来那个 key 了，重新 `/列表` 即可。

**检测名单**（要监控哪些模型名，比如 `gpt-5.6-sol`、`claude-opus-5`）默认**每池一份**，
存在 `models/<池名>.txt`，一个模型名一行，**默认是空的**——空名单就不采集、列表里
显示「待检测」。要全局共用一个名单，把 `model_list_mode` 改成 `"shared"`（用
`models/shared.txt`）。

## 快速开始

要求：Python 3.10+（只用标准库），一个 OneBot v11 实现（例如 NapCat）已在同机或
可访问的网络里跑着。

```bash
git clone <本仓库>
cd qq-keypool-bot

cp config.example.json config.json   # 然后按下面的字段表改
python3 bot.py --selftest            # 不联网的端到端自检，先看这条通不通
python3 bot.py                       # 起服务（默认监听 127.0.0.1:3020/onebot）
```

把 OneBot 的「事件上报 / HTTP POST」指到 `http://127.0.0.1:3020/onebot`，
机器人就会用 `onebot_url + /send_group_msg` 回消息。

系统服务、定时任务、以及**让 AI 帮你部署时该问什么**，见 [DEPLOY.md](DEPLOY.md)。

## 配置字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `onebot_url` | str | OneBot v11 的 HTTP API 地址（发消息用，如 `http://127.0.0.1:3000`） |
| `onebot_token` | str | OneBot 的 access_token，没有就留空 |
| `listen_host` / `listen_port` | str / int | 本服务监听事件上报的地址与端口 |
| `self_qq` | int | 机器人自己的 QQ 号 |
| `group_whitelist` | int[] | 只服务这些群，其他群的消息一律忽略 |
| `daily_group_whitelist` | int[] | 每日播报发到哪些群（可以留空 `[]`） |
| `pool_mode` | str | `per_group`=每群一个池（默认）；`shared`=所有群共用一个池 |
| `model_list_mode` | str | `per_pool`=每池一份检测名单（默认）；`shared`=全局共用一份 |
| `seq_limit` | int | 池内序号上限，默认 99 |
| `insecure_tls` | bool | 探测时是否跳过 TLS 证书校验（自签站点才需要打开） |
| `http_timeout` | number | 单个 HTTP 请求超时秒数 |
| `secondary` | object | *可选*：备用机保底复测，默认 `{"enabled": false}`，见下 |

**`secondary`（可选，默认关）**：如果主机的出口 IP 老被站点挡（比如 Cloudflare），
可以把 `relay_probe.py` 放到另一台机器上，配好 SSH 免密，然后：

```json
"secondary": {
  "enabled": true,
  "ssh_target": "relay",
  "script_path": "/opt/keypool-relay/relay_probe.py",
  "label": "备用"
}
```

主机在「被 CF 拦截」或「判死/连不上」时会经 `ssh relay python3 …` 让备用机复测一遍；
两台结论冲突时以备用机为准且**不删除**，并在 `/查询`、`/列表` 里标出「（备用）」。
不配这一段就是纯单机，功能完全一样。

## 定时任务

两个脚本都可以挂在 systemd timer / cron 上（用哪个随你，推荐 systemd）：

```bash
python3 update.py     # 每小时：按池采集模型状态（公开接口，不消耗 key）
python3 daily.py      # 每天：测活 + 探余额 + 判死即删 + 发播报
```

两个脚本都接受 `--config` / `--database` / `--models-dir`，默认用当前目录下同名文件。

## 常见问题

**Q：为什么列表里有的模型只有绿勾、没有百分比？**
站点没提供公开的统计接口，或者这个模型最近没人调用过，拿不到可用率。这种情况只给绿勾，
**不编造数字**。

**Q：什么情况下 key 会被自动删掉？**
只有两种：① 明确「余额耗尽」（402/429 且响应里带余额类关键词）；② 站方明确回
「Invalid token / 无效的令牌」。401/403 认证拒绝、CF 拦截页、连不上、5xx **一律保留**
——站点瞬时误报很常见，宁可留着让群友自己再试一次。

**Q：为什么 `/查询` 打错的序号没有任何回复？**
因为下架是**物理删除**，「已被删除」和「从来没有过」在库里分不出来，所以对不上号就
不回复（不打扰群）。同一个原因：`/查询` 只在本群的池里找。

**Q：为什么不把 key 打码？**
刻意的产品决定：群里的人就是要**拿去用**的，打码等于没用。所以只能投你自己愿意公开的 key。

**Q：需要装什么包？**
不需要。纯标准库，`python3` 就能跑，这也是为什么它能在最便宜的小机器上趴一整天。

**Q：为什么不用 AI 来判断 key 有没有死？**
规则是明确的（状态码 + 关键词），用固定分支比让模型「看着像死了」可靠得多，也快、
不要钱、不会漏 key。
